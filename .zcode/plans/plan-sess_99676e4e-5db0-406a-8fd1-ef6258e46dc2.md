# Conjure 隔离预览（bridge 跨域模式）实施方案

## 背景
AI 生成应用当前在主域（30031）直接打开预览，存在 AI 恶意/失误代码窃取主域用户资料的风险。改为：预览统一在 `http://localhost:30032/bridge/` 隔离域运行——conjure（30031）通过 noneos-core 的 remoteUser 应用间通信把生成的应用文件推送到 bridge（30032），bridge 写入自己的虚拟文件系统后经虚拟挂载 URL 打开应用。`npm run static` 已同时伺服 30031–30036，30032 无需新增服务。

## 协议与流程

1. 用户点「预览应用」→ conjure 取本地用户 `getUser("conjure-preview")`，注册服务 `conjure-preview`，新标签打开 `http://localhost:30032/bridge/?u=<conjureUserId>`。
2. bridge 页安装/确认 NoneOS Core（nos-version 模式，参考 run-app：CDN 完整 URL，因 SW 注册前 /gh/ /nos/ 不可用）→ `getUser("conjure-bridge")` 创建自己的用户，注册服务 `conjure-bridge` → `connectUser(?u=)` → `sendToService("conjure-preview", {type:"hello", userId: bridgeUserId})`（带 waitForService + 重试，直到 conjure 应答 ready）。
3. conjure 收到 hello → `connectUser(bridgeUserId)` → 读取应用文件（VFS 渠道读 `ai-apps/<name>/client/`；本地渠道复用 `readAppFiles(handle)`，`/mz/app-runner.js` 已导出，优先 client/ 子目录）→ 按 reliable-messaging 规范逐条串行推送（msgId + ACK + 超时重发 + 去重，单条 ≤128KB；大文件按 seq/total 分片）：
   - `{type:"app-begin", appName, fileCount}` → `{type:"file", appName, path, seq, total, text}`（每文件末片带 end 标记或单独 `file-end`）→ `{type:"app-end", appName}`。
4. bridge 收到 app-begin 先清空 `conjure-apps/<name>/`，逐片拼装写入 `conjure-apps/<name>/client/<path>`（`init("conjure-apps")`），收齐 app-end 后回 `{type:"done", url}` 并 `location.href = "/$conjure-apps/<name>/client/index.html"` 跳转运行。
5. conjure 侧状态经 store `keyError`/toast 提示（推送中/完成/失败）。

## 文件变更

**新增**
- `bridge/proto.js`：双端共享协议模块——`SERVICE_ID_CONJURE = "conjure-preview"`、`SERVICE_ID_BRIDGE = "conjure-bridge"`、消息类型常量、可靠投递实现（信封 `{msgId, kind: "data"|"ack", payload}`、sendReliable 带 ACK 超时重发、接收端 ACK 先于去重、`seenIds` TTL 清理、按目标串行队列、128KB assertSendable）。双端同仓库同源，直接绝对路径 `/bridge/proto.js` 引用。
- `bridge/index.html`：功能性单页（非 o-app 页面模块，参考 run-app 的自包含写法，资源走 CDN 完整 URL）——nos-version auto-install + 进度 UI；Core 就绪后注册服务、解析 `?u=`、握手 hello、接收文件写 VFS、跳转运行。用户命名空间 `conjure-bridge`。
- `official-apps/conjure/lib/remote-preview.js`：conjure 侧编排——`openRemotePreview({ appName, mode, getFiles, load, onStatus })`：注册 `conjure-preview` 服务、打开 bridge 标签、等 hello、connectUser、串行推送文件、等 done。bridge origin 常量默认 `http://localhost:30032`（顶部常量便于改）。

**修改**
- `official-apps/conjure/lib/builder-store.js`：新增 `openAppRemote(appName, mode)`——VFS 渠道直接读 `ai-apps/<name>/client/`（`listAppFiles` + `readAppFile`），本地渠道恢复句柄后用 `readAppFiles(handle)`；调 remote-preview，状态写入 `keyError`/新 state 字段；原 `openApp` 保留为兜底不暴露。
- `official-apps/conjure/pages/home.html`：顶栏与新应用落地卡片的预览按钮改调 `store.openAppRemote`。
- `CONTEXT.md`（根）：目录树加 bridge/ 说明。
- `official-apps/conjure/CONTEXT.md`：新增「隔离预览」小节 + 速查表条目。

## 关键约束遵循
- bridge 页 SW 注册前资源全部 CDN 完整 URL（同 run-app 例外规则）；Core 就绪后 `/nos/*` 经 `load()` 按需加载。
- 通信遵守 reliable-messaging 五要素；文件为 UTF-8 文本（与 share 约束一致），单文件超限自动 seq/total 分片。
- bridge 只写独立命名空间 `conjure-apps`，与主域数据无交集，达到隔离目的。

## 测试

## 验证（手动）
`npm run static` 后：30031 打开 conjure 生成/选中应用 → 点「预览应用」→ 自动开 30032/bridge/ 标签 → 安装 Core → 显示传输进度 → 跳转 `/$conjure-apps/<name>/client/index.html` 运行应用；30032 的 storage/VFS 中无主域用户数据。
