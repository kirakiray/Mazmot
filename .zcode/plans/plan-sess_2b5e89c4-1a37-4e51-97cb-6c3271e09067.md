# cred-manager「互授」页面实现计划

## 目标

在 official-apps/cred-manager 新增「互授」导航页：双方在同一页面输入对方匹配码即可互相看到卡片；授权方推送证书后，对方实时收到并可一键保存到本地。基于 noneos-core 的 `registerService` / `sendToService`（用户所说的 service-registry），并用 cred-hub `POST /creds` 做离线兜底。

## 消息协议（lib 层自建可靠层）

按 noneos-core reliable-messaging 规范：每条消息带唯一 `msgId`，接收方回 ACK（`ctx.remoteUser.sendToService` 原路回复），发送方超时重发复用同一 `msgId`，接收方按 `msgId` 去重。消息类型：

- `match` — 携带本方签名 profile card（A 解析 B 匹配码后发给 B，B 端记录"谁匹配了我"）
- `grant` — 携带授权证书数组 + issuer 卡片
- `ack` — 通用回执

## 关键技术点

- `/nos/user/main.js` 顶层 import 禁止 → 页面里 `const load = lm(import.meta); await load("/nos/user/main.js")`
- LocalUser / RemoteUser 实例挂 `this._xxx`（ofa.js 规则）
- cred-hub 上传兜底：grant 时先 `POST {server}/creds`（key 格式 `role-issuer-subject`），成功后再 push；对端保存时优先用消息内证书体，失败则按 key 从 cred-hub 拉
- 服务只在应用打开时存在：对端离线时 UI 明确提示"对方不在线，授权已存入 cred-hub，对方上线后可在本页拉取"
- 证书签名验证：收到的 grant 证书保存前走既有校验路径（`user.cred.import` 自带验证；profile card 用 `verifyProfileCard`）
