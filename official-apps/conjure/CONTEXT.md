# 妙造（Conjure）上下文说明

妙造（Conjure）是对话式 AI 应用生成器：用户描述需求，AI Agent（`mz/ai/chain` 工具循环）生成完整的 ofa.js 应用并写入文件系统，完成后可直接预览运行。支持多应用、每应用多会话；写入渠道二选一——虚拟系统（VFS `ai-apps/<name>/client/`）或本地目录（`fs.open()` 选盘上目录，仅 Chrome，文件写入所选目录的 `client/` 子目录）。本文件是本应用的**活文档**，与代码保持一致；修改代码必须同步更新本文件（规则见 [AGENTS.md](AGENTS.md)）。

> 核心心智模型：**用户在草稿态发出首条消息即创建项目**（建目录 + 登记 + 切换上下文 + 首个会话都在发送时落地，不等回合结束——中断 / 关页的回合也归属项目，下次进来接着迭代；草稿桶恒为空）；写入目标（虚拟 / 本地）在草稿阶段选定、随项目锁定；每个应用下挂多条会话（独立消息 + 独立 Agent 记忆）；右侧面板管理应用，左侧边栏是当前应用的历史会话列表。

## 技术栈

- **ofa.js** 页面模块（`<template page>`），单页应用，无路由跳转
- **依赖 URL（自包含规范）**：
  - **ofa.js**：所有文件（含入口 HTML）一律 `/gh/ofajs/ofa.js@latest/dist/ofa.mjs#debug`（本地前缀，NoneOS Core Service Worker 拦截），必须带 `#debug`；jsdelivr 完整 URL 仅限仓库根 `index.html` 与 `apps/run-app/` 等 Core 引导入口，本应用内禁止写死
  - **ofa.js router**：`/gh/ofajs/ofa.js/libs/router/dist/router.min.mjs`（无版本号）
  - **Senti-UI**：主题引导 `boot/st-boot.js` + 页面内按需 `l-m` 声明的 `st-tab-bar` / `st-tab-item`（面板 tab）、`st-button`（新建应用 / 预览应用等主按钮 + 输入区发送/停止圆形按钮——`color="error"` 语义换停止色，尺寸形状由页面 CSS 覆写）、`st-icon-button`（顶栏应用列表 / 面板关闭 / 新建对话）、`st-menu` / `st-menu-item`（输入区模型 / 推理等级 / Key / 窗口钻入式选择菜单）；一律 `/gh/ofajs/senti-ui@latest/packages/...`（始终 `@latest`）；禁止其他来源的组件资源
- **AI Agent**：`/mz/ai/main.js`（`getAssistant` / `getApiKeys` / `onApiKeysChange`）+ `/mz/ai/chain/main.js` 的 `createAgent` + `tool` + storage 版 checkpointer；assistant 选择：用户在输入区 select 手动指定的 key 优先（`activeKeyId`，deepseek 供应商配 `deepseek-flash` 模型名，其余跟随供应商默认），模型同理可手动指定（`activeModelId`，须属于当前 key 的可用清单）；模型选项**动态获取**：仓库 `refreshModelOptions` 对当前生效的 key 调 `assistant.getModels()`（relay 供应商即 `/v1/models`），结果按 keyId 缓存在 `modelOptionsCache`（成功 `[{id,label}]` / 失败 `null` 回退 `MODEL_OPTIONS` 内置表 / 无记录未拉取）并投影到 state `modelOptions`；**静默自动拉取**：进应用 / key 列表变化 / 手动切换 key 时自动执行，「自动」模式下解析 `pickAutoKey`（lib/builder.js 纯函数）将命中的那把 key，无需用户手动点开菜单；未指定时自动——`pickAutoKey` 选 key（deepseek 优先 / 仅一台时锁定 / 多台随机负载均衡），DeepSeek 配 `deepseek-flash`，relay 未指定模型时由 `RelayAssistant` 自行静默取上游 `/v1/models` 首个可用模型（不写死厂商模型名，避免撞用户模型白名单 403）；未配置 Key 时发送报错提示去「AI 密钥管理器」。key 列表镜像在 state `apiKeys`，`onApiKeysChange` 实时刷新，选中项被删/禁用自动回退自动模式；**模型 / 推理等级 / Key / 窗口**四项选择全部收在输入区右侧的 `st-menu` 钻入式菜单里（触发器为「模型 · 等级」描边 Chip 按钮——与底部统计条同族：8px 圆角 + outline-variant 描边，四个根项各挂 `sub-menu` 子菜单——hover 展开、选中任意项整链自动关闭、面板 fixed 定位自动翻转避让视口，开合/Esc/点外部全由组件自理；选中项 prefix 显示 ✓，取值走 suffix slot）。**推理等级**存 `pref:reasoning`（off / minimal / low / medium / high / max 全档位集），**可选项跟随当前模型动态生成**——仓库 `refreshEffortOptions` 按「当前生效 key 的供应商 + 选中模型（未选取清单首项）」调 `/mz/ai/efforts.js` 的 `effortLevelsFor` 生成 state `effortOptions`（各家档位不同：DeepSeek/GLM-5/Kimi-k3 为 low·high·max 系、OpenAI gpt-5 系为 minimal~high 且不可全关、Qwen 仅 off·low（enable_thinking 开关）、Anthropic / gpt-4o 不可调 → 空表显示「当前模型思考不可调」），同时把偏好夹取为生效档位 `effectiveReasoning`（`clampEffort` 就近向下，空表为空串显示「默认」）——菜单项与触发器文案都按生效档位展示；注入 Agent 时（`ensureAgent`）按同一 `clampEffort` 夹取（null = 模型不可调则不发思考参数，efforts 加载失败按偏好原样兜底）；key / 模型 / 偏好任一变化即重算，切换即 `invalidateAgent` 下回合生效（旧版布尔思考模式偏好 `pref:thinking` 首次读取时迁移）。**底部统计条**（Material Design 3 视觉：位于输入框下方的状态行——原「内容由 AI 生成，请注意甄别」免责声明已删除、由该行顶替，左对齐）：触发器为**描边 Chip**（8px 圆角 + outline-variant 描边，悬停 on-surface 8% state-layer，开启态 secondary-container 实底、去描边；图标 primary 色）：会话统计（N 轮 M 步 · TPS，面板含模型用时 / 工具调用用时 / 首 token 平均 TTFT / 输出速度）+ Token 用量（共 N tok · 缓存命中 %，面板含未缓存输入 / 缓存读取 / 输出分桶）+ 上下文占用（Chip 内嵌 4px 微线型进度条 + % 标注，≥80% 转警示色；面板含分解色条——secondary / tertiary / primary 三段全圆角色条、段间留缝——与图例及「压缩上下文」filled-tonal 全圆角按钮）；无数据的胶囊**降级显示而非隐藏**（完全无记录的空会话才不渲染）：会话统计缺步数 →「N 轮 · 统计缺失」、用量缺失（`statMissingTurns` 个已收尾回合无 usage）→「用量缺失」+ 面板「数据缺失」行、上下文拿不到任何 usage（`ctxUnknown`）→「未知」+ 说明行——老会话/异常收场丢统计时如实告知缺了什么；面板点击开合互斥（`openStat`，Chip 同步 `class:open` 高亮；面板为 **elevated card**：16px 圆角 + 细描边 + surface-container 底，**常驻渲染**、`opacity + 自锚点 scale` 做 emphasized 入场/退场动画（`cubic-bezier(0.2,0,0,1)`，transform-origin 随对齐变体）——o-if 挂卸做不了退场动画，`prefers-reduced-motion` 下关闭），数据源为消息上的 `turnStats` / `usage` / `contextBreakdown`（页面 `syncStats` 聚合）。进度**回合中途即实时刷新**——chain 工具循环每次中间模型调用返回后推 `usage` 事件（用量 + 统计 + 分解的累计快照），仓库写进 state `liveTurnStats`（不依赖文本气泡——模型不说话直接调工具的步同样刷新；消息只承载既往回合，live 补足进行中回合，相加不重复），页面随状态事件重算，不必等回合结束的 `done`）
- **宿主能力（站内绝对路径 `/xxx` 引用，Service Worker 保证运行时可用）**：
  - `/nos/fs/main.js`：VFS 写入（`init("ai-apps")`）与本地目录选择（`fs.open()`，仅 Chrome）
  - `/nos/storage/main.js`：持久化——本应用自身状态存 `getStorage("conjure")` 独立空间，生成应用登记读写 `getStorage("mazmot")` 空间的 `apps` 键（详见「数据模型」）
  - `/mz/app-runner.js`：`readAppFiles`（隔离预览本地渠道收集文件，优先 client/ 子目录）；原主域直开 `getRunUrl({ source: "local", _handle: appDir })` 已退居兜底
  - `/mz/net/main.js`：联网能力（web_fetch / web_search 工具底层）——`fetchText` 抓取网页文本、`searchWeb` 联网搜索（jina 不支持搜索），通道固定 / relay 多台选择 / 自动优先级解析，`ensureAgent` 惰性加载后经 `netFetch` + `netSearch` 注入工具 ctx
- **数据安全约定**：写库前把响应式对象拍平为纯对象（避免代理入库）；noneos 句柄等非响应式数据放下划线开头的模块变量（如 `localRootHandle`），防 ofa.js 响应式包装
- **图标**：删除按钮等图标用 `<n-icon icon="mdi:xxx">`（页面已声明 `<l-m src="/nos/n-icon/n-icon.html"></l-m>`），禁止直接依赖 `iconify-icon`；其余 UI 主要用 emoji 与内联 SVG
- **视觉**：不强制 senti-ui 组件，可按需自写；颜色体系遵循 M3 设计语言（CSS 变量 `--md-sys-color-*` 配对 token），不写死十六进制色

## 工具插件体系

`lib/tools/` 下每个工具一个**独立包目录** `<tool>/`：`index.js`（插件本体，默认导出 `{ key, name, description, schema, exec(args, ctx) }`，具名导出 `selfTest` 内置测试模组地址；视觉工具另导出 `visual` / `tags` / `testTags`）、`self-test.js`（内置测试模组，见「工具详情对话框与包内置测试」）、`README.md`、`test/<tool>.sb.html`（包测试，不分发）。`index.js` 注册中心的 `createTools({ tool, fs, rootHandle, onAppCreated, onFileWrite, readSkill, requestForm, openPreview, previewDebug, onPreviewShot, netFetch, listPreviewWindows, checkPopup })` 构造共享 `ctx` 并用 chain 的 `tool` 工厂包装，返回按 `key` 索引的映射（页面用 `Object.values(tools)` 喂给 Agent）。新增工具 = 建包目录 + 在注册中心登记，导出 `selfTest` 即自动获得对话框「内置测试」Tab。

## 视觉交互表单（show_form 工具）

带 UI 交互的工具：模型调用 `show_form` 传入表单规范 `{title, description, fields[]}` → builder-store `requestForm` 把表单卡片作为一条 `role:"assistant", type:"form"` 消息推入当前回合并返回 Promise（挂起本轮对话直到用户交互）→ 用户在卡片上填写并点「提交」（组件内收集控件值，required 缺失 toast 拦下）→ `store.submitForm(msgId, values)` 把 `{status:"submitted", data}` patch 回消息（随会话桶持久化）并把数据 resolve 给工具，工具以 `{"data":{...}}` JSON 返回给模型继续。用户点停止 / 回合兜底结束时 `cancelPendingForm` 置 `cancelled` 只读。卡片由 show-form 包内的视觉组件 `<show-form-card>`（`form-card.html`，页面经 `l-m` 声明预载）渲染：`data.spec` 接收表单规范（页面传 `:spec="$data.form"`），pending 时 `renderFields` 生成 senti-ui 表单控件（st-input / st-textarea / st-select / st-radio / st-checkbox，宿主页面须 l-m 预载这些控件；st-radio 以 name 为同组互斥键、value 属性为提交值），全部文本经 `esc` 转义防注入，提交时组件内部收集控件值（senti 控件 value 走 property、checked 走属性）、required 校验后 emit `form-submit`（bubbles + composed，ofa emit 的载荷在 `event.data` 即表单值）→ 页面 `onFormSubmit` → `store.submitForm`；**历史回填与恢复**：重新打开会话时提交过的表单以「label：值」清单只读展示（badge「已提交 · 只读」）；pending 表单**原样保留**（消息经增量落盘持久化），刷新后仍可填写提交——此时无活动等待器，`submitForm` 走 `resumeFormTurn` 恢复回合：因检查点只在回合收尾落盘，本轮对话不在模型记忆里，恢复 = 把「user 请求 → assistant 调 show_form → 工具结果（提交数据）」合成写入 `thread:<id>`，再以空输入重新驱动 agent 循环（`driveTurn`，与 send 共用收尾）；无 API Key 时报错且表单保持 pending 可重试。

## 技能知识库（运行时下载到 VFS）

Agent 的「查文档」能力，技能**不内置**在应用内：启动后后台任务按技能源清单从远端下载（zip 或裸 `SKILL.md`），安装到 VFS 根命名空间 `skills/<id>/`（`init("skills")`），`read_skill` 读取的也是这份虚拟目录副本（下载一次后离线可用）。

- **源清单**：`DEFAULT_SKILL_SOURCES` 为默认种子——`ofajs-docs.zip`、`noneos-core-docs.zip`、`senti-ui-skill.zip` 三个 raw.githubusercontent URL + 站内同源路径 `/.agents/skills/mazmot-api.zip`（随站点部署分发的官方技能，源地址写 `/` 开头相对路径、fetch 按当前域名解析）。首次运行写入自存储空间 `skill-sources` 键，之后以存储为准（`getSkillSources` / `setSkillSources`，预留管理 UI 扩展点）。默认清单演进走**版本化增量迁移**（`skill-sources-ver` 键 + `DEFAULT_SKILL_SOURCES_VERSION`）：已播种过旧清单的存储在版本落后时把新增的默认源追加合并进清单（用户手动登记的源原样保留）并更新版本，新增默认源对老用户即时生效；默认清单变更时必须 bump 版本号
- **同步流程**（`syncSkills`，`ready()` 里 `backgroundSyncSkills()` 后台触发、不阻塞首屏）：逐源下载 → sha256 与 `skills/<id>/__meta.json` 里记录比对，同内容跳过写入 → zip 经零依赖解析（`unzipText`：手读中央目录 + `DecompressionStream("deflate-raw")`，支持存储/deflate）→ `stripCommonRoot` 剥掉单一根目录 → 只落文本扩展名文件 + `__meta.json`；单个源失败不中断其余，离线时保留已有副本
- **索引与读取**：`loadSkillIndex(fs)` 遍历 skills 空间各目录的 `SKILL.md` frontmatter（含 `version`，有则列表显示 v 徽标），并从 `__meta.json` 带出 `source`（下载地址）与 `installedAt`；`readSkillFile(fs, id, path)` 只放行 `.md`、拦截 `..` 逃逸与非法 id，超 60000 字符截断提示精读 references
- **手动安装 / 更新**（右侧资源面板「技能」tab）：「＋ 添加」按钮弹出 prompt 输入 zip 包或 `SKILL.md` 地址（https URL 或站内 `/` 开头的同源路径）→ 仓库 `installSkillFromSource(url)` 先把 loading 占位放入 `skills` 列表（同 id 已存在则原地置 loading，即更新语义）→ `installSkillFromUrl(fs, url)` 下载安装（同内容 sha256 一致跳过写入）→ 刷新索引、置空 `agent`，并把该地址登记进自存储 `skill-sources`（之后后台同步也会持续检查；`setSkillSources` 只放行 https 与站内 `/` 路径）。失败回滚 loading 占位并由 alert 提示。每个技能 item 下方展示来源地址，行尾刷新按钮从来源更新；`idFromUrl` 由 URL 推导技能 id
- **接线**：页面初始化 `skillIndex = await loadSkillIndex(fs)`（失败不阻塞）→ `ensureAgent` 注入 `readSkill: (id, path) => readSkillFile(fs, id, path)` 并把 `skills: skillIndex` 传给 `buildSystemPrompt`（提示词尾部「可用知识库」清单；硬性约束含「写模板 / 用组件前禁止凭记忆，必须先 read_skill」）；后台同步有实际写入时刷新 `skillIndex` 并置空 `agent` 重建提示词

`ctx.rootHandle` 是本地渠道的根目录句柄；缺省时所有写入走 VFS `ai-apps/`。**新增工具**：建插件文件 → `TOOL_DEFS` 登记 → 按需更新 `SYSTEM_PROMPT`（均在 `lib/` 内，页面零改动）。

## 双写入渠道与锁定规则

- **草稿阶段**（`currentAppName === ""`）：输入区显示「📁 虚拟系统 / 📂 本地目录」切换器（渠道只是偏好）；选本地需先 `fs.open()` 选目录（句柄存模块变量 `localRootHandle`，非响应式），选中既有项目则直接走导入流程。
- **发送即创建（createProjectNow）**：草稿态发出首条消息时立即用当前偏好创建项目——应用名取请求文本 slug（中文取不出用 `app-<时间戳>` 兜底）→ `createAppDir` 建目录 + 占位 app.json → mazmot 登记记录（本地句柄随之落库）→ registry 建首个会话 → `applyApp` 切换上下文；`mode` 从此随项目锁定，后续会话的 `ensureAgent` 按 `currentAppMode` 注入句柄，切换器不再显示。
- **首回合（freshTurn）**：仓库记录刚创建的项目标记，`ensureAgent` 据此切换「空项目生成」提示词变体（跳过 create_app，第一个文件写正式 app.json）并从工具清单移除 `create_app`；模型覆写 app.json 时经 `onFileWrite` → `syncAppMetaFromDisk` 把正式 displayName/icon 回填 registry 与顶栏；回合收尾（`finishTurn`）出预览卡片——中断 / 出错的回合同样出卡，如实呈现项目现状。freshTurn 标记回合结束即清，后续回合走正常「已存在应用」提示词。
- **项目规则自动加载（AGENTS.md）**：已存在项目的 Agent 重建时（`ensureAgent`），宿主自动读项目 `client/AGENTS.md` 并整节注入系统提示词「项目规则（已自动加载，必须遵守）」——项目规则随会话开始自动生效，不依赖模型自觉去 read_file（这是 AI 开发 harness 的常规机制）；超 6000 字符掐头留尾截断并提示 read_file 读全文；模型每次覆写 AGENTS.md 后下一回合（agent 重建时）即读到新版。**新项目的文档骨架由宿主整套预写**：`createAppDir` 建目录时把 `lib/agents-template.js` 的四份模板写入 client/——AGENTS.md（`buildAgentsMd`，通用规范）+ CONTEXT.md / MEMORY.md / pitfalls/README.md（`buildProjectDocs`，带 `<!-- skeleton` 首行标记与「待填」占位的骨架）；各自仅在缺失时写（同名覆盖重建不清空，已定制内容不丢）。文档补写放在模型工作流程末尾，生成中途被截停（工具步数上限 / 手动停止 / 报错）时整套会缺失，存在性必须由宿主保证，模型只负责填充：提示词要求 AGENTS.md 不重写、特有硬规则只追加在「硬性约定」节末尾，其余三份填充为真实内容且不能留占位交差；「已存在应用」回合读到骨架占位或文档缺失时先补齐再干活；较早期生成的项目没有 AGENTS.md 时，「已存在应用」提示词内嵌完整模板让模型一次性补建。项目文档体系为**四件套**：AGENTS.md（通用规范，自动注入）/ CONTEXT.md（项目事实 + 踩坑索引，活文档）/ MEMORY.md（记忆体，每回合追加，上限 50 条、将满压缩最旧 20 条成 3–4 条）/ pitfalls/（一坑一文件 NNN-slug.md，按索引按需精读）。
- **本地句柄恢复与授权**：nos-storage 按**路径引用**存句柄，`fs.open()` 得到的本地目录**必须先 `fs.mount()`** 才能 `setItem`（未挂载句柄无法还原，存储直接抛错）——`chooseLocalDir` 选完目录即挂载，挂载产物（path 为 `$mount-*`）入库存档。切换应用 / 刷新后从记录恢复（`getLocalHandleFromRecord`，内部 `fs.get(path)` 还原）。恢复到句柄后用 `ensureLocalPermission` 检查权限——已 granted 直接可用；仅剩 prompt 状态则 `requestPermission`（借助用户手势）补授权；补授权失败才回退重新选目录。权限待授予时提示条带「🔑 授权目录」按钮（`permGrantNeeded` + `grantLocalPermission`）。`chooseLocalDir` 里用户取消选择器（`AbortError`）静默返回 false，不当失败报错。
- **应用内显式重建**：已选应用的会话里用户明确要求重做时模型仍可调 `create_app`（`onAppCreated` → `adoptNewApp` 迁移路径保留为兜底；正常生成流程不再经过它）。

## 隔离预览（bridge 跨域推送）

AI 生成的应用**不在主域运行**：预览按钮（顶栏 + 新应用落地卡片）一律调仓库 `openAppRemote(appName, mode)`，把应用文件推送到隔离域 bridge 运行——AI 代码接触不到主域的用户资料与 IndexedDB。隔离域 origin（`remote-preview.js` 的 `BRIDGE_ORIGIN`，按 `location.hostname` 自动选择）：本地开发 `http://localhost:30032/bridge/`（`npm run static` 同伺服 30031–30036）；线上（非 localhost 域名）统一 `https://c1.dev.mazmot.noneos.com/bridge/`（同一份静态站的独立子域，与主站不同 origin 保持隔离）。原主域直开逻辑 `openApp` 保留为兜底、无 UI 入口。

**双路径自动选择**（`remote-preview.js`，bridge/agent 侧 userId 持久化在自存储 `bridge-user-id` 键；**服务只注册一次**——模块级单例 + 共享 waiters + `lastPeerSeenAt`（最近一次对端信封时间），重复 `registerService` 会抛 already registered）：

- **快路径（应用页代理在线）**：首次预览后应用页内常驻 `/bridge/inject.js` 代理（receiver 写 index.html 时注入 `<script type="module" data-conjure-id=...>`，幂等；比对 hash 前经 `stripAgent` 剥离，与发送端原始内容对齐）。代理注册 `conjure-agent` 服务并上报 `agent-online`；再次预览时先做**三信号在线判定**（`isAgentLikelyOnline`：① 本地缓存 `isRemoteUserOnline`——注意它只反映「本页实例已建立的连接」，`remoteUsers` 缓存是页级的，**新开/刷新后的 conjure 标签页缓存为空会把开着的代理误判为离线**；② 近期对端信封 8s 宽限 `lastPeerSeenAt`；③ 有界主动连接探测 `probeConnect`（`connectUser` 6s 上限，连上即进入缓存并同时服务后续推送））——**判定在线则绝不走 bridge 引导页**：直连代理 `sync-check`（8s）→ 增量推送 → 代理落盘后回报 done 并 `location.reload()` **无感刷新**，零差异秒回不刷新；探测失败但 `lastPeerSeenAt` 在 15s 宽限内、或本回合连接探测刚成功过（`probedOnline`，新标签页里 `lastPeerSeenAt` 为 0 的场景），会换新等待器再等一轮，仍失败才回退。
- **慢路径（首次预览 / 应用页已关）**：以**独立新窗口**（popup，非新标签，便于与妙造并排对照）打开 `bridge/?u=<userId>` 引导页，走 hello → sync-check → 推送 → done → 跳转 的完整流程；`window.open` 固定窗口名 `mazmot-bridge-preview` + 尺寸/位置 features（窗口跳转成应用页后即承载代理，回退时被复用聚焦）；被浏览器拦截（返回 null）时报错提示允许弹出式窗口。

**多窗口（上限 `MAX_PREVIEW_WINDOWS = 10`，本机 popup 与手机扫码设备平等）**：

- **窗口注册表**（`remote-preview.js` 内存 Map，key = `userId|sessionId`）：每个预览窗口里的代理以 **15s `announce` 心跳**（appName/url/ua）上报；conjure 侧 45s 无心跳判离线、30min 清条目。同机多窗口共享 bridge 域 userId，**只能靠 sessionId 区分**——announce 经服务消息携带 `ctx.fromSessionId` 天然带会话标识。UI 下拉气泡（预览按钮点开，`state.previewWindows` 快照）展示**窗口方块网格**（两列，每格 = 缩略图 + 在线点 + 应用名 + 设备标签 `describeDevice(UA)`；离线淡显灰点标失联时长）与**跨设备二维码**（`/bridge/?u=<conjure userId>&app=<应用>`，`m-ercode` 渲染，链接头尾省略展示 + 复制按钮；本机多窗口走「新开窗口」按钮，不设单独地址）。**方块缩略图（wire 指令，免授权）**：气泡打开时与打开期间每 5s 经 `refreshPreviewThumbs` 逐个在线窗口定向发 `wire` 调试指令，两级策略——① 首选 **snapdom**（`bridge/vendor/snapdom.mjs`，v3.3.0 MIT vendor 本地）真实渲染截图：open shadow DOM / 字体 / 渐变全保真，JPEG dataURL（宽 440、q0.7、dpr1，exclude 代理胶囊，backgroundColor 取页面自身底色）直出，仅 ~8KB/张；方块内 `object-fit: contain` **完整显示整个应用**（源图底色与留白同色，视觉无缝）；② snapdom 失败回退 `wireSnapshot` 线框节点清单，`lib/thumb-paint.js` 在主域 canvas 重绘近似图。两者都不需要屏幕授权且**移动端 Safari（无 getDisplayMedia）可用**；传的是数据/像素而非代码，不执行 AI 生成逻辑，隔离边界不受影响。snapdom 克隆页面会实例化宿主框架自定义元素触发噪音报错——抓图期间经 `capture.setMuted(true)` 静默控制台捕获，防「截图自身」的报错污染 AI 错误感知。结果存 `state.previewThumbs`（按 winId 缓存，过期守卫防旧结果写入；失败置空串由占位图兜底）。
- **扫码 / 新开窗口自动推送**：bridge 引导页 hello 带 `?app=` 期望应用名 → conjure 服务 handler 触发 `onBridgeHello` 钩子（`setPreviewHooks` 接线）→ `pushToWindow` 收集文件走 `syncPreviewPeers` 串行推送（内部 `pushChain` 队列与按钮主流程互斥）；超上限时 conjure 回 `preview-full` 通知（引导页显示错误页 / 代理胶囊显示上限提示）且不注册。顶栏气泡「新开窗口」= `openPreviewWindow`（槽位窗口名 `mazmot-bridge-preview-<n>` 防复用旧窗）。
- **更新全部窗口**：预览按钮主推送完成后，`runRemotePreview` 读取注册表把其余在线窗口（排除主窗口对端 `getPrimaryBridgeId`）经 `syncPreviewPeers` 逐个增量同步（对端先按常驻代理试探、失败回退 bridge 引导页流程），失败逐个吞掉不阻断。
- **定向调试**：`debugPreviewCommand({ winId })` 解析目标（显式 winId → 注册表精确匹配；缺省 → 最近心跳的在线窗口；注册表为空回退存储的 bridge userId 广播兼容旧窗口）；`dbgLink` 的 sendTo 按 **msgId 记档投递目标**（重发同目标），`sendToService` 带 `sessionId` 精确到窗口不广播。回合等待器带 `expectedPeer` 防其他窗口的 hello/agent-online 冒领本轮等待。

**流程**（双端共享协议 `/bridge/proto.js`：服务 ID（`conjure-preview`/`conjure-bridge`/`conjure-agent`）、消息类型、`sanitizeAppName`/`validateRelPath` 守卫、`chunkText` 字节分片（预算 32KB；**切点按 code point 对齐**——孤立代理项经 TextEncoder/E2EE 变 U+FFFD 不可逆损坏。历史另有一独立根因：noneos-handshake 服务器日志截断 `&text[..500]` 按字节切片在多字节字符上 panic、连接静默死亡——大分片「整窗丢失」曾长期被误诊为跨区域中继/尺寸问题，上游 ceb3309 已修复，test-bin 二进制为修复版）、`sha256Hex`+`buildManifest`（文件指纹清单）、`createReliableLink`（信封 + ACK + 超时重发 + msgId 去重 + 串行队列，单条 ≤128KB；ACK 等待与重试次数均按载荷字节放宽——每 16KB 等待 +1s、每 32KB 追加一次重试（上限 +5）：noneos 文档明确通道切换期间消息可能丢失，大分片需更长总重试窗口等通道回稳；`onOffline` 钩子带 reason——capped（sendTo 超时无响应，连接疑似僵尸）时消费方应硬重置连接、not-delivered 软检查即可，且**每次主动重连授予 +1 重试额度（封顶基础 +2）并缩短重连后等待**——曾实测「最后一次尝试才触发重连但额度已尽直接拒绝」的重连白做；`sendCapMs` 单次 sendTo 8s 封顶——noneos 内部命令超时可长达 45s，不封顶会拖垮重试节奏；`onEvent` 事件日志钩子——attempt/sent/send-capped/reconnect/ack/duplicate/rejected 全链路可追踪，默认 console.debug，测试收进失败 content）；`enableServerAutoReconnect(user)`——**noneos 服务器自动重连默认关闭**，CI 中继长连接被杀后用户会永远停在 offline（实测 WebKit CI ACK timeout 的根因），各端 getUser 后必须立即开启（baseDelay 1s、退避至 15s）；`ensureServerConnected(user, {hard})`——双端**收敛到排序首位的同一台中继**（对非首选 URL 先发制人 disconnect，防 getUser 后台 connectAll 的迟到握手把会话挂回多台；localhost 源下默认列表的 `ws://localhost:8081` 排序必胜，CI 用 test-bin/ 本地信令服务器即由此闭环），hard 时首选也 disconnect+connect 重建治僵尸）、`createFileAssembler` 分片拼装；接收端核心在 `/bridge/receiver.js`）：

1. `openAppRemote` 经 `collectAppFiles` 收集应用全部文件——VFS 渠道 `listAppFiles` + `readAppFile`；本地渠道恢复句柄（`getLocalHandleFromRecord` + `ensureLocalPermission`）后复用 `/mz/app-runner.js` 的 `readAppFiles`（优先 client/ 子目录）。
2. `remote-preview.js` 的 `openRemotePreview({ load, appName, files, selfStore, onStatus })`：`getUser("conjure-preview")` → **服务只注册一次**（模块级单例 + 共享 waiters，重复 `registerService` 会抛 already registered）→ 等信令服务器连接 → 按上述双路径选择对端。
3. **增量同步**：发 `sync-check`（`buildManifest` 的「路径 + sha256」清单，每条约 80 字节），对端比对本域 VFS 后回 `sync-diff`（需重传的 path 列表）；conjure 只推送差异文件（部分命中 → `app-begin` 带 `wipe:false` 覆盖写入，全部命中/全新 → `wipe` 全量清目录重建），无差异时跳过推送直接等 done；比对超时（慢路径 30s）/异常回退全量。比对规则（receiver）：注入的代理脚本先 `stripAgent` 剥离再比对（与发送端原始内容对齐）；**存量迁移**——本地 `index.html` 内容一致但缺注入标记（注入功能上线前写入的）时强制列入重传，一次性补注入，此后走正常增量。
4. bridge 引导页（`bridge/bridge.html`，Core 引导入口、资源走 jsdelivr 完整 URL）：**域名白名单守卫先行**（入口 `bridge/index.html` head 内联经典脚本 + `bridge.html` 页面模块两道锁，canonical 实现在 `bridge/host-guard.js`——仅 `*.dev.mazmot.noneos.com` 子域与本地开发 localhost 放行，主站 apex 域名 / 任意其它域名整页阻断；防恶意页面 window.open 主站域名上的 `/bridge/?u=攻击者userId` 注入任意代码）→ nos-version 自装 Core → `getUser("conjure-preview")` → 注册 `conjure-bridge` 服务 → 连接 `?u=` 指定的 conjure 用户 → hello → 收 `sync-check` 经 `createPreviewReceiver`（消息串行化处理）比对并回 `sync-diff`，已最新则直接进入启动流程；否则按 wipe 语义写入 `conjure-apps/<name>/client/`（路径经 `validateRelPath` 复检，index.html 注入代理脚本）→ app-end 后回 done；跳转前经 `waitUrlReady` 轮询 URL 可访问（首装 Core 后 SW 激活存在窗口期，立即跳转会 404）再跳 `/$conjure-apps/<name>/client/index.html`。
5. 应用页代理（`bridge/inject.js`）：页面加载即注册 `conjure-agent`、连接 conjure 上报 `agent-online`；收到更新走同一 `createPreviewReceiver`（带 `conjureId`，重写 index.html 时保持注入），app-end 后回 done 并 reload；代理启动失败不影响应用本身运行。页面内常驻**可拖拽的「隔离预览」状态胶囊**（挂 `documentElement`——应用重写 body 不受影响，MutationObserver 被移除时自动回挂；`position`/`z-index`/`left`/`top` 等关键样式内联 `!important` 压制应用 CSS；Pointer Events 拖拽 + 视口钳制、位置记忆 sessionStorage）：状态点 idle 灰 / busy 黄（接收更新 n/m，联动 receiver onProgress）/ ok 绿（已连接妙造 / 已是最新 / 刷新中）/ offline 红（连接失败或未连妙造）。胶囊右侧**「日志」按钮**打开控制台日志面板：`installConsoleCapture` 挂接 log/info/warn/error/debug/time·timeLog·timeEnd/table 与 window error / unhandledrejection，带毫秒时间戳入环形缓冲（800 条，对象/Error 栈/DOM 节点安全序列化，单条截断 2000 字）；`createLogDialog` 用 **Shadow DOM** 渲染（应用 CSS 无法穿透，宿主仍带 `!important` 定位保护），为**双视图**：「控制台」（等级过滤 全部/错误/警告，带计数徽标 / 清空 / Esc 或按钮关闭，打开期间实时追加并自动滚底）与「妙造调用」（conjure 调试指令操作记录，见「隔离预览调试」节的调用记录条目）；**顶栏可拖拽**（Pointer Events + 视口钳制，按钮点击不触发拖拽，位置记忆 sessionStorage）。

**状态反馈**：state `previewBusy`（防重入，按钮禁用）/ `previewStatus`（过程提示，顶栏预览按钮左侧小字，经通用 patch 投影到页面）；失败写 `keyError`。

**推送完成 = 代理可用**：done 后若发生了文件写入（页面将 reload / 引导页将跳转成应用页），`openRemotePreview` 会继续等下一轮 `agent-online`（30s 超时不视为推送失败，仅告警跳过）再返回——调用方（预览按钮 / `preview` 工具 action=app）返回时预览页已在跑新代码且调试代理可响应，紧接着的调试指令不会扑空；零差异（无刷新）跳过等待。仓库层 `openAppRemote` 为 UI 包装（吞错），主流程在 `runRemotePreview(appName, mode)`（失败写 `keyError` 并抛出，供工具层感知）。

## 隔离预览调试（preview 工具，dbg 指令通道）

让 Agent 像 Playwright MCP 一样调试**实际运行中的**预览应用，形成「写文件 → preview(action=app) 运行 → 读控制台/查 DOM/模拟交互 → 修复 → 再运行」闭环（系统提示词的工作流第 3 步强制此循环）。**用户反馈界面/运行问题时先用 action=status 判定预览是否在线**：在线直接现场取证（action=console 不传 since 拉全部缓冲等），不先 action=app——重推会刷新页面、清空控制台缓冲，丢失报错现场；离线才 action=app 拉起。**弹窗拦截恢复流程**：预览窗口经 `window.open` 打开，而推送链路有多个 await（建用户/连信令），浏览器视为非用户手势，默认拦截自动弹窗（`window.open` 返回 null，不弹任何提示）——首次预览经常撞上且用户无感知。此时 `openRemotePreview` / `openPreviewWindow` 抛 `code=POPUP_BLOCKED` 专用错误（`popupBlockedError`），preview 工具识别后给模型返回行动指引而非失败文案：指导用户放行（地址栏弹窗图标 → 始终允许本站）→ **停下等用户回复确认** → action=check-popup 验证（`checkPopupAllowed`：试开空白小窗立即关闭，已放行会闪现小窗属预期）→ action=app 重推；系统提示词工作流同款约束，防止模型在放行前原地重试。指令在 30032 预览页内的常驻代理执行（`/bridge/debug-runtime.js`，纯页面逻辑无 /nos 依赖），主域不执行任何 AI 代码。

- **协议**（`/bridge/proto.js`）：conjure → 代理 `{type:"dbg", cmd, args, reqId}`；结果回传 `{type:"dbg-chunk", reqId, seq, total, text}`（大结果按 `chunkText` 同 32KB 预算分片）+ `{type:"dbg-result", reqId, ok, result|error, chunks?, meta?}` 汇总；`buildDbgResultMessages` / `createDbgCollector` 为双端构造/聚合实现（纯逻辑单测覆盖）。
- **链路**（`remote-preview.js`）：调试走**常驻 `dbgLink`**（与预览回合的 `activeLink` 并存互不干扰；服务 handler 按 `payload.type` 定向路由，`kind:"ack"` 信封两条链路都尝试结算各自 pending）；`debugPreviewCommand({ load, selfStore, cmd, args, timeoutMs, winId })` 解析目标窗口（见上「多窗口·定向调试」）→ 发指令（默认 25s / 上限 120s 等结果，`reqId` 配对 `dbgWaiters` 结算）；预览未打开 / 不在线抛可读错误并引导先调 `preview`（action=app）。
- **指令集**（`debug-runtime.js`，实现参考同作者 web-bridge-mcp 的 client.js）：`status`（URL/标题/视口/日志统计）、`console`（读 `installConsoleCapture` 环形缓冲，`since` 增量拉取、返回头带最新 ts）、`text`（innerText）、`click` / `type`（scrollIntoView + click / 聚焦写值派发 input·change）、`wait`（轮询等元素出现/消失或 JS 谓词，200ms 间隔）、`dom`（DOM 样式快照：每可见节点一行几何 + 关键 computed style + 文本，穿 shadow DOM，免授权的「虚拟截图」）、`eval`（任意 JS，预置 `$`/`$$`/`$deep`/`$$deep`（穿 shadow DOM）/`$wait`/`$rect`/`$css`/`$import`；表达式自动 return / 语句块末句表达式自动补 return；结果安全序列化 30k 字符封顶）、`shot`（getDisplayMedia 真实截图，每次独立授权、**截完（含失败路径）立即停止全部轨道**不留常驻共享状态，JPEG 默认 maxSide 1280 / q0.72 压缩后 base64 回传）、`wire`（**窗口方块缩略图数据**，两级：首选 vendor 的 snapdom 真实渲染截图（免授权、shadow DOM 保真、手机可用），失败回退 `wireSnapshot` 线框节点清单（文档坐标、穿 shadow + light 双向遍历、剔除 conjure-* 代理元素、上限 150 节点）交 thumb-paint 重绘；AI 工具层不暴露）。
- **安全**：代理端只信任注入时绑定的 conjure 用户（`ctx.fromUserId !== conjureId` 直接忽略——调试指令可执行任意 JS，必须校验发送方）；eval/type 等全部在隔离域页面内执行，主域零暴露。
- **调用记录（可观测）**：每次 dbg 指令经 `createOpLog` 记入操作日志（工具名 + `summarizeDbgArgs` 参数摘要 + 成败耗时；sessionStorage 持久化、按页面加载分组，上限 5 组 × 100 条），预览页胶囊「日志」面板新增**「妙造调用」视图**可查（与「控制台」双 tab，实时刷新，视图偏好记忆 sessionStorage）——用户能看到 AI 对预览页做过的每一步操作。
- **工具层**（`lib/tools/preview/index.js`）：**单一 `preview` 工具 + `action` 参数分发**（app/windows/check-popup/status/console/dom/text/click/type/wait/eval/screenshot；screenshot 映射 dbg 指令 `shot`），操作专属参数放 `args` 对象，顶层 `winId` 可选定向目标窗口（action=windows 列注册表清单：id/应用/设备/在线/心跳）；exec 内做各 action 的必填参数校验与结果超时表（screenshot 90s / wait 按其 timeoutMs 放宽 / console·eval 30s / 其余默认 25s）；action=app 走 `runRemotePreview`（返回即代理可用；`code=POPUP_BLOCKED` 错误转放行指引文案），action=windows 走 `ctx.listPreviewWindows`，action=check-popup 走 `ctx.checkPopup`，其余走 `debugPreviewCommand`；截图经 `ctx.onPreviewShot` 把 dataUrl 以 `role:"image"` 消息卡片展示给用户（模型无法看图，工具文案引导布局核验用 action=dom）。工具图标在 home.html `toolIcon` 映射登记。

## 发布到首页应用列表

生成的应用默认只活在妙造内（主系统 apps.html 的 `loadApps` 过滤 `mazmot.source === "ai-builder"` 记录）。**发布 = 把当前应用 client/ 复制一份到常规应用命名空间 `mazmot-apps/<发布名>/client/`**（`builder.js` 的 `publishAppToHome`，仓库层 `publishCurrent`），并登记一条普通虚拟应用记录（`mazmot.source: "conjure-publish"`，无 ai-builder 标记）——首页列表天然可见，点开走 NoneOS 挂载路径直接运行，与妙造工作目录相互独立：删妙造项目不影响已发布副本，首页删副本也不影响妙造项目；**本地目录渠道同样以复制发布**，副本不依赖本地句柄（换设备副本照常打开）。版本写在 app.json（首发用现值 0.1.0；内容有变化的再次发布 patch +1 写回源 app.json 后全量重拷副本——清空旧 client/ 再写，避免上一版残留文件；内容与上次发布一致则幂等重发不 bump）。发布名沿用上次（重复发布地址稳定），首次发布时避开已有记录名与既有目录（冲突加 `-2`/`-3` 后缀；妙造源记录自己的名字让给副本）。源登记记录（ai-builder 标记，首页始终隐藏）记发布元数据：`published` / `publishedVersion` / `publishedAt` / `publishedHash`（发布内容指纹，含刚写回的版本号）/ `publishedVersions: { [hash8]: version }`——备份清单据此给内容一致的备份挂「已发布 vX.Y.Z」徽标（`refreshBackups` 映射，备份 id 尾部即指纹）/ `publishedName`（副本目录名）。复制清单用 `currentAppFiles`（与智能备份同源，只收集 client/）——不能用 `listAppFiles`：本地渠道它按项目根 `flat()` 枚举，client/ 外文件（backup/ 等）路径剥不掉前缀原样返回，逐个读不到返回 null，`dest.write(null)` 即报 `WriteParams` 错（实测踩坑）；拷贝循环在版本写回**之后**重新收集（复用开头快照会把旧版本号拷进副本，实测踩坑）。发布成功时仓库 `publishCurrent` 同步在备份管理打一条带正式版本号标注的备份（`renameAppBackup` → label「发布 vX.Y.Z」；命中已有同内容备份且用户已命名时不覆盖）。副本记录带 `appId`（`${发布名}-${当前用户 userId}`，仓库 `publishCurrent` 经 share-mgr `ensureUser` 取）——首页列表据此显示「我开发的 / Mine」自建标记；并默认 `autoShare: true`，主系统列表加载时对其自动 P2P 发布（`_runAutoShareAll` → share-mgr `publishApp`，回写 payloadHash 到副本记录）。**发布动作本身同步做一次 P2P 分享发布**（`publishCurrent`：对副本 handle 调 `publishApp`，payloadHash / fileHash 回写副本记录，shareUrl 记进源记录 `mazmot.publishedShare`）——失败不阻断发布，首页列表打开时 autoShare 自动重试。气泡显示分享链接行（`shortUrl` 短显 + 复制按钮；`refreshPublishState` 优先读 `publishedShare.shareUrl`，否则按副本 payloadHash 现场拼 `buildRunUrl`；未生成时显示「打开首页应用列表后自动生成」）。UI：顶栏发布按钮点击**不下直接发布**，弹出下冒气泡（`.publish-pop`，交互同预览气泡：外点 / ESC 关闭）展示发布状态——未发布 / 已发布 vX.Y.Z 徽标、发布版本、代码状态（`publishMatch`：true「发布内容就是当前代码」/ false「有未发布的修改」，`refreshPublishState` 按指纹对比计算，applyApp 切应用时刷新）；按钮「🚀 发布 / 🚀 更新发布」，发布 / 幂等重发均 toast 反馈，失败进 keyError 横幅；按钮未发布 `mdi:rocket-launch-outline` / 已发布 `mdi:rocket-launch` 主色高亮，title 显示当前发布版本；`publishedInfo` 随 applyApp 同步、回草稿清空。首页删除副本按「记录名 + 命名空间」匹配，不会级联删掉同名妙造源记录。

## 回合变更卡、自动快照与预览自动检测

三项联动机制（对齐 codex/cursor 的 diff 审查 + checkpoint 与 harness 的自动反馈回路），数据全部挂在**回合末条 AI 消息**上：

- **变更追踪**：`write_file` / `edit_file` 的 `onFileWrite` 回调带 `prevText` / `nextText`（builder 的 `writeAppFile` 返回 `prevText`、`editAppFile` 返回前后全文），store 闭包 `turnChanges` 同文件多次写只保留「**首改前 + 末改后**」；回合收尾一次性重算统计与**行级内容并冻结进末条 AI 消息**：`changes: [{path, op, adds, dels, hunks?}]`（`hunks` = `compactHunks(diffLines(首前, 末后), 3)` 的 ±3 行上下文折叠序列，单文件超 200 行不保留只留统计 + `tooLarge` 标记；`prevText` 为 null = 新文件全行 add 不产生 del；宿主预写的骨架不经回调、不计入）——**冻结后展开看到的永远是该回合自己的净变化**，与磁盘后续变化（后续回合 / 回滚）无关（此前"快照 vs 当前盘"的实时对比会让旧卡片混入最新代码，已废弃为兼容路径）
- **回合开始快照**（`driveTurn` 开头，草稿态跳过）：`createAppBackup(fs, app, handle, { auto: true })` 内容寻址幂等快照（无改动与既有备份同 id 零成本），id 挂末条 AI 消息 `snapshotId`；`__meta.json` 带 `auto: true`（`listAppBackups` 透出，备份抽屉可识别），`pruneAutoBackups` 只保留最近 10 个 auto 备份（手动备份不动，防 backup/ 撑爆；被清理的旧回合快照使其变更卡回滚按钮失效——但冻结 diff 仍可查看）。
- **变更卡 UI**（AI 正文下方 `.turn-changes`，**占满消息列宽**，VS Code 式交互）：头行 = 图标 + 「本回合改动」+ 文件数 + 右对齐 ±统计徽标（增删分色）+ 旋转箭头（单开互斥 `changesMsgId`）；文件为**内容自适应宽度的芯片**（`.tc-files` flex 换行，芯片按标题自然宽、超 320px 省略），点击**选中**（primary 高亮）→ 下方**共享 diff 面板**显示该文件的行级 diff——内容**优先读消息内冻结的 `change.hunks`**（该回合自己的净变化，同步展示）；仅旧卡片（未记录 hunks 的兼容回合）降级走 `store.getTurnDiff(app, snapshotId, path)` 现场对比快照与当前盘，头部标注「该回合未记录行级内容，正在对比当前盘」——面板只随「有无选中」开合动画、切文件仅换内容（**切换不清空旧内容**——旧 diff 保留展示 + 头部「正在加载…」，新内容就位后按前后实测高度做一次 200ms 显式高度过渡（双 rAF 后量目标值，`prefers-reduced-motion` 跳过），消除清空重填的高度跳变闪动；过期响应守卫 `_diffToken` 防快速连点乱序）；diff 行红绿语义色（`attr:type` + 属性选择器），空态区分「内容一致」与「加载失败」；卡片展开/收起与 diff 面板均为 **grid 0fr→1fr 纯 CSS 高度动画**（`.tc-collapse` 容器，内容常驻挂载、收起过程不消失，`prefers-reduced-motion` 关闭）；底部操作行**仅当前会话最后一个带改动的回合可操作**（`turnActionsAvailable`：从消息尾部找最后一个带 changes 的回合比对 id）——历史回合隐藏全部按钮、显示「历史回合，仅可查看当时的改动」（diff 冻结内容不受影响，只能看）。**变更卡整体在消息列表 o-fill 的项模板内——页面级数据与方法引用必须走 `$host.`（`$host.fileDiffPath` / `$host.showDiffEmpty()` 等），裸字段名在项作用域解析到消息对象、全部静默落空（面板空白，实测踩坑两次）；内层芯片 o-fill 同理。且 `$host` 方法绑定必须**带括号调用**（`on:click="$host.backupTurnCode()"`）——裸方法引用（无括号）被 ofa 当作函数引用挂监听器，`this` 脱离组件代理，方法内部的 `this.xxx` 全部失效（实测踩坑：备份按钮点击报 backupDisabled is not a function）**。
- **回滚（单按钮 + 语义选项）**：变更卡底部主按钮「回滚」——点击原地展开两个语义选项（选择本身就是确认，无额外两步确认）：「不满意，撤销」（error 色描边，`sentiment: "dissatisfied"` + `requestText` 该回合用户请求摘要）与「仅还原代码」（中性）。执行均为 `rollbackTurn(app, snapshotId, opts)` = `restoreAppBackup`（unchanged 如实返回）+ 登记 `pendingRollback` + `invalidateAgent` + `syncAppMetaFromDisk` + 刷新备份列表；对话记录不受影响。
  - **「已回滚」派生态**：回滚成功后当前内容与该回合快照一致 → `turnReverted(msg)`（`backups` 含 `id === snapshotId` 且 `current` 的项，`refreshBackups` 在回滚/回合结束/切应用后刷新）为真 → 按钮 `attr:disabled` + 文案「已回滚」；此后文件再变化会自动恢复可点。与「备份代码 → 已备份」对称。
  - 「回滚对话重来」（fork + 还原）入口已从卡片移除——对话分支走 AI 消息上的 ⎇ fork；`forkTo`（自 `forkSession` 抽出的共用尾段）保留供 fork 使用。
- **AI 感知（pendingRollback 通知）**：回滚后登记 app 级待消费通知；`send` 侧失效缓存 Agent，`ensureAgent` 传 `buildSystemPrompt({ rollback })` 注入「回滚通知」节（中性："以 read_file 结果为准，勿凭记忆写回已撤销内容"；不满意：含被否决回合的请求摘要，"不要原样重写、按新指示行动，教训按规范沉淀 pitfalls/"）；`driveTurn` 开始消费清除（一次性）。
- **预览自动检测回路**（`autoCheckPreview`，回合收尾 fire-and-forget）：本回合有文件改动 && `previewOnline`（**不自动开窗**）&& 非手动停止 → `runRemotePreview` 推最新代码 → 等 2.2s → `previewDebug("console")` 过滤 `[error]` 行（≤6 条）挂 `state.autoErrors`；下回合 `send` 开头 `invalidateAgent`，`buildSystemPrompt({ autoErrors })` 注入「预览自动检测报告」节（修复是默认最高优先级，除非用户另有指示），`driveTurn` 开始时取走清空（不跨回合重复注入）；输入区上方提示条展示（可 `dismissAutoErrors` 忽略本次）。重入保护 `autoCheckBusy` 防连发回合叠加。


## 数据模型

### 存储空间 `conjure`（本应用自身状态）

| 键 | 值 | 说明 |
|----|----|------|
| `apps-registry` | `[{ name, displayName, icon, mode: "vfs"\|"local", createdAt, sessions: [{ id, title, createdAt, updatedAt, duration? }], sessionOrder?: [id...] }]` | 应用注册表（含内嵌会话列表）；`duration` 为累计对话耗时毫秒（`finishTurn`/`adoptNewApp` 每回合累加，会话级统计）；`sessionOrder` 为手动拖拽排序登记（可省略，缺省按 `updatedAt` 倒序；不在登记里的新会话按最近更新排最前） |
| `chat:<app>:<sid>` / `chat:draft` | 消息数组（同页面 `messages` 结构，含 `role: user/assistant/tool/app/image` 条目；user 条目可带 `images`（dataURL 字符串数组，多模态输入——图片随消息持久化并在气泡内缩略展示，发送时仓库组装为 OpenAI content 数组 `{type:"text"} + {type:"image_url"}` 交给支持视觉的模型）；assistant 条目带 `reasoning`（思考过程文本）/ `model`（回答模型徽标）/ `reasoningOpen`（思考块折叠状态）/ `usage`（回合 token 用量，挂在回合末条 AI 消息上，含 DeepSeek 的 `prompt_cache_hit_tokens` 缓存命中与供应商回报时的 `reasoning_tokens` 推理 token；`context_tokens` 为当前上下文占用估算，进度条用）；image 条目带 `src`（dataUrl）/ `w` / `h`（preview 工具 action=screenshot 的截图卡片）；assistant 条目另可带 `stopped`（true = 本回合被用户手动停止，ai-foot 显示「已手动停止」徽标）、`turnMs`（本回合耗时毫秒，收尾 patch）、`turnStats`（chain 回合执行统计：steps / llmMs / toolMs / ttftMs / ttftSteps / decodeMs / decodeTokens）、`contextBreakdown`（上下文构成估算：systemTokens / toolsTokens / messageTokens）——四者在回合收尾时（done 落值；停止 / 异常收场（步数上限、网络错误等无 done）由 driveTurn finally 把累计实时快照补挂）挂到回合内末条 AI 消息上（单载体，仓库剥旧防重复累计；正常完成时消息已有 usage，守卫跳过不重复）；进行中的回合以 state `liveTurnStats` 实时快照呈现、不写消息 | 各会话消息；`chat:draft` / `thread:draft` 仅兼容保留、恒为空（草稿发送即建项目，`startDraft` / `init` 清除遗留数据） |
| `thread:<threadId>` | wire 格式消息数组 | Agent 会话记忆（checkpointer）；`threadId` = 应用名 `:` 会话 id，草稿为 `draft` |
| `pref:reasoning` | string（`"off"` / `"minimal"` / `"low"` / `"medium"` / `"high"` / `"max"`） | 推理等级偏好（菜单选项按当前模型动态生成，`setReasoning` 持久化，`init` 恢复并迁移旧 `pref:thinking`；注入 Agent 前经 `clampEffort` 夹取到模型支持档，`thinking` = 夹取档非 off，`reasoningEffort` = 夹取档） |
| `pref:ctx-window` | string（token 数，如 `"786432"`） | 上下文窗口大小偏好（默认 768k；菜单切换 128k/256k/512k/768k/1mb，`applyCtxWindow` 时持久化，`ready` 时恢复） |
| `pref:active-key` | string（key id 或 `""`） | 对话用 API Key 偏好（`""` = 自动负载均衡；`selectApiKey` 时持久化，`init` 时恢复；key 失效自动回退 `""`） |
| `pref:active-model` | string（模型 id 或 `""`） | 对话模型偏好（`""` = 供应商默认；`selectModel` 时持久化，`init` 时恢复；不属于当前 key 供应商时自动回退 `""`） |
| `ui` | `{ app, session }` | 上次停留位置，`ready` 时恢复 |

### 存储空间 `mazmot` 的 `apps` 键（生成应用登记）

- 虚拟渠道（`buildAppRecord`）：`{ name, desc, icon, source: "virtual", namespace: "ai-apps", dirName: "ai-apps/<name>", virtualDirName, handle: null, createdAt, mazmot: { source: "ai-builder" } }`
- 本地渠道（`buildLocalAppRecord`）：`{ name, desc, icon, source: "local", namespace: "", dirName: name, handle: <DirHandle>, createdAt, mazmot: { source: "ai-builder" } }`
- 登记按 `name + namespace` 去重更新（`registerAppRecord`）；删除用 `unregisterAppRecord`（按 `mazmot.source === "ai-builder"` + name 匹配）；列表查询 `listRegisteredApps` 过滤 `namespace === "ai-apps" || mazmot?.source === "ai-builder"`
- 主系统（main/）应用列表：**生成应用一律不进主列表**——虚拟应用落在独立命名空间 `ai-apps/`（不与主系统共享的 `mazmot-apps/` 混用），本地渠道记录仅供妙造（conjure）持久化恢复句柄；主系统 `loadApps` 按 `mazmot?.source === "ai-builder"` 过滤隐藏全部生成应用

### 磁盘 / VFS 落点

- 虚拟渠道：`init("ai-apps")` 根下 `<name>/client/`（运行 URL `/$ai-apps/<name>/client/index.html`）；删除应用时递归删该目录（`deleteVfsApp`）
- 本地渠道：应用文件统一写入**用户所选目录的 `client/` 子目录**（`resolveBaseDir` 按 `rootHandle` 分流，与虚拟渠道布局一致）；预览挂载该 `client/` 目录（`getRunUrl` 本地逻辑，无 `client/` 时回退挂载根目录——兼容历史写在根上的旧应用）；**删除应用不删盘上文件**，只移除登记。历史旧应用的文件在所选目录根上，继续编辑时会在 `client/` 下重建（旧文件不受影响）
- **本地项目导入**：草稿阶段选中本地目录时，若目录里已存在 `client/app.json`（既有项目，`detectLocalProject` 探测），走**导入流程**而非新建——按 app.json 元数据在本应用 registry 与 mazmot apps[] 登记（句柄随记录落库），并从项目目录的 `conjure-chats.json` 恢复会话列表、消息与 Agent 记忆（只补本机缺失的会话，不覆盖本地已有记录），完成后 `selectApp` 切换到该项目；发送中触发的导入（`prepareContext` 草稿分支选完目录发现已切换）会继续按既有应用走会话准备，本轮对话直接落进导入的项目
- **对话快照（conjure-chats.json）**：本地渠道应用的每次回合结束（`finishTurn` 尾部与新建应用落地后）调用 `syncLocalProjectChats`，把会话列表（含 `sessionOrder`、`duration`）、各会话消息（进行中的回合优先取内存桶）、Agent 记忆（`thread:*`）全量写入项目目录 `client/` 同层的 `conjure-chats.json`，供下次导入时同步对话数据；写入失败仅 console.warn 不影响对话
- **数据备份**：两种渠道均在 `client/` 同层落 `backup/<id>/` 目录（虚拟渠道为 `ai-apps/<name>/backup/<id>/`，本地渠道为所选目录 `backup/<id>/`；id 形如 `backup-20260908-153012-<hash8>`，尾部为内容 hash），打包时按原相对路径复制 client/ 全部文本文件并忽略 `node_modules`；内容与已有备份相同则跳过（toast 提示「内容未变化」）；备份可更名与加备注（自定义 label / note 存备份目录内 `__meta.json`，列表优先显示 label——无则回退格式化时间，备注有则显示在目录名下）；两者的编辑合并为一个 `st-dialog` 对话框（名称 st-input + 备注 st-textarea，保存时一并写入；放在 `.app` 层避免抽屉 transform 影响 fixed 遮罩）；每个备份项可还原——confirm 确认覆盖风险后写回，无备份时 confirm 引导先创建备份，当前内容与备份一致时 toast 提示无变动，与当前一致的备份项显示「与当前一致」徽标（store `refreshBackups` 依据 `currentAppHash` 标记 `current` 字段，该项隐藏还原按钮）；入口为顶栏预览按钮旁的「备份管理」按钮 → 右侧加宽抽屉（列表 + 新增备份 + 智能备份 + 还原 + 编辑 + 两步确认删除）；「✨ 智能备份」在打包后用 AI 对比上一版备份自动生成标题与备注（见 builder-store `smartBackup`）

## 状态仓库（lib/builder-store.js）

AI 创作 / 运行过程的全部业务逻辑封装在 `createBuilderStore({ fs, mazmotStore, selfStore, load })` 返回的可观察状态对象中，页面不持有任何业务状态，只订阅事件更新视觉数据。这样「进行中的对话切换应用」等上下文切换都在仓库内部单一代码路径里完成，不会出现页面作用域变量错乱。

**事件契约（`store.subscribe(cb)`）**：

- `{ type: "patch", data }`——state 标量 / 整组数据更新（data 为键值对；`nextId` 为内部计数，页面忽略）
- `{ type: "messages", op, ... }`——消息流水线细粒度变更：`op: "replace"`（带 `list`）/ `"push"`（带 `item`）/ `"patch"`（带 `id, patch`）/ `"splice"`（带 `id`）

**每会话消息桶（切换会话不串台的关键）**：每个会话（含草稿）在 `sessionBuckets: Map<chatKey, 消息数组>` 里有独立的消息桶，`state.messages` 只是「当前查看会话」桶的视图镜像（事件只在操作目标桶 === 当前视图时才发给页面）。发送回合开始时固定 `turnKey`（本回合所属 chatKey），流式消息 / 工具事件 / `finishTurn` 落盘全部路由到该桶——用户中途切到别的会话/项目也不受影响，切回时 `loadSessionById` 检测到 `key === turnKey` 直接投影内存实时桶（不读盘覆盖）。`nextId` 全局单调递增防多桶 id 撞车。删除正在流式的会话/应用时中断回合并丢弃实时桶（`finishTurn` 见桶不存在即跳过落盘）。`toggleTool` / `toggleReasoning` 作用于当前视图桶（可能与回合桶不同）。同一时间只允许一个回合（`sending` 互斥），回合归属会话在左侧列表项上有 `busy` 标记（loading 图标，随 `currentAppSessions` 条目的 `busy` 字段下发，`syncCurrentFromRegistry` 重建列表时按 `turnKey` 复原）。**消息增量落盘**：push / patch / remove 消息即触发防抖 400ms 的桶落盘（`scheduleSave(key)`，捕获当下 key 防收尾后写错桶）——刷新 / 意外关闭不再丢失进行中的回合；`finishTurn` 仍做最终落盘。

**state 字段**：`messages` / `sending` / `stopRequested`（用户点了停止、回合尚未收尾——停止按钮禁用显示「停止中」，防重复点击；收尾时清零）/ `liveTurnStats`（进行中回合的实时快照 `{ usage, stats, breakdown }`，`usage` 事件写入、收尾清零；底部统计胶囊与上下文进度的中途刷新数据源）/ `reasoning`（推理等级偏好 off / minimal / low / medium / high / max，随 `pref:reasoning` 持久化）/ `effortOptions`（推理等级菜单可选项，按当前模型动态生成）/ `effectiveReasoning`（夹取后的生效档位，空串 = 模型思考不可调）/ `activeModel`（当前 Agent 的模型标识，AI 消息徽标用）/ `keyError` / `coreError` / `nextId`（消息与发送）；`apps` / `currentAppName`（`""` = 草稿）/ `currentAppDisplay` / `currentAppIcon` / `currentAppMode` / `currentAppSessions` / `currentSessionId` / `currentSessionTitle`（顶栏展示的当前会话标题，`syncSessionTitle` 从 registry 解析，草稿/无会话为空）（应用与会话）；`storageMode` / `localDirLabel` / `permGrantNeeded`（写入目标与授权）；`skills`（技能索引镜像）；`backups`（当前应用备份 id 清单，新的在前）/ `backupBusy`（打包中防重入）/ `smartBackupBusy`（智能备份的 AI 分析阶段）/ `previewBusy` / `previewStatus`（隔离预览推送中与过程提示）/ `previewOnline`（预览窗口内应用页代理在线状态，驱动顶栏预览按钮亮标；由 `init` 时启动的 `watchPreviewAgent` 常驻监听维护——noneos `remote_user_connected`/`remote_user_disconnected` 事件（精确匹配预览用户 id，断开清 `lastPeerSeenAt` 立即熄灭）+ 5s 轮询 `isRemoteUserOnline` 兜底（页面隐藏暂停、回前台即刷；8s「见过信封」短兜底防 reload 抖动误灭；新标签页/刷新后本地连接缓存为空时每 ≥30s 一次有界 `connectUser` 探测，代理页开着即点亮，探测建立的连接同时服务后续预览快路径；预览完成后 `refreshWatcher` 立即点亮，慢路径另延时 3s 补一次等代理上线））；`apiKeys` / `activeKeyId`（对话用 Key 镜像与选中项）/ `activeModelId`（手动选中的模型）/ `autoErrors`（预览自动检测收集的 error 行，见「回合变更卡」节）。

**图片附件（多模态输入）**：输入框直接**粘贴**截图（`on:paste` 读 clipboardData 的 image file）或点 composer-row 右簇的回形针按钮（`#imgPicker` 隐藏 file input，`accept="image/*" multiple`，选完重置 value 便于重选同图）→ `normalizeImage` 规范化为 dataURL（GIF 与 ≤400KB 小图原样保留；超 1280 长边或 400KB 的位图 canvas 缩到 1280 长边 + JPEG 0.85 压缩——请求体与 IndexedDB 都省）→ 待发缩略图 `.attach-row`（每张 56px chip + × 移除，上限 8 张 `MAX_PENDING_IMAGES`，发送中不可添加）→ 随下一条消息发出（`handleSend` 收集 `pendingImages` 传 `store.send(text, images)`，纯图片消息可发——发送按钮 disabled 条件为 `canSend()`：有文本或有待发图）。已发送图片在用户气泡内缩略展示（`.user-imgs`，`msgImages` 兼容老消息无 images 字段），点击 `openImage` 转 blob URL 新开标签看大图（dataURL 顶层导航会被浏览器拦）。

**会话 fork（分支对话）**：聊天由线性会话构成，每条 AI 消息底部的 usage 行旁有「⎇ fork」按钮（`canFork()` 限定已落地会话且非发送中）→ `store.forkSession(id)` 创建分支：当前会话的聊天记录复制截至该消息（含）为新会话（同应用 registry 下新 `sid`，标题为原标题 + `⎇`），Agent 记忆 `thread:<app>:<sid>` 经 `truncateThread` 按完整回合截断复制（fork 点所在回合若因中途停止而未闭合——末条 assistant 仍带 tool_calls——该回合整段舍弃，防悬空 tool_calls 打崩后续请求），随后 `loadSessionById` 切换到新会话，两侧从此各自独立演化。左侧会话列表支持拖拽排序：HTML5 drag 事件（`sessionDragStart/Over/Leave/Drop/End`，拖过项显示上缘指示线），落点调仓库 `reorderSessions(fromId, toId)` 持久化到 registry 的 `sessionOrder`；对话进行中的项 loading 替代删除按钮槽位且不可删除（`deleteSession` 对 `turnKey` 命中的会话兜底拒绝）。对话计时展示在右侧聊天区：所有消息入桶时统一打上落盘时刻 `ts`（`pushMessage` 补齐）；非 AI 消息 hover 才显示时间（`.msg-ts`），AI 消息的时间与本轮耗时固定在 `ai-foot` 行最右侧（`.ai-time`，如 `17:09:11 · 2分05秒`；本回合被手动停止时左侧多一枚 error 色「已手动停止」徽标 `.ai-stopped`）；usage 行是「本轮用量」小号描边 Chip（`.stat-pill.sm`，`⛁ 用量 X tok` 紧凑总量，开启态同族 secondary-container 高亮），点击弹出明细面板（复用 `.stat-panel` 左对齐变体：提供方 / 模型、缓存命中 %——部分命中四舍五入会到 100 时降位显示 99.9、未缓存输入、缓存读取、输出及「其中推理 X tok」，`openUsageMsgId` 单开互斥、点外部/Esc 收口——统计胶囊与用量 Chip 的 document 级 mousedown 收口（`attached` 挂的 `_docClose`）判定「是否点在锚点内」**必须走 `e.composedPath()` 穿过 `.stat-anchor`**：页面内容在 shadow DOM 里，document 层事件的 target 已被 retarget 成宿主元素，`e.target.closest(".stat-anchor")` 永远命中不了 shadow 内的锚点，会把面板内的每次按下（含面板上选字复制）都误判成点外部直接关面板，已开胶囊再点也会先被关、click 的 toggle 又打开（表现为重复弹起而非切换）；同因由 `openStat` 面板一并适用，Esc 收口（`_docKey`）无 target 不受影响）；回合进行中「生成中…」右侧由页面每秒 `clock` 心跳实时计时（`turnLiveText`，依赖仓库状态 `turnStartTs`，回合结束清零），回合结束后 `send` 收尾把本轮耗时 `turnMs` patch 到回合末条 AI 消息上随会话桶落盘。消息事件（含流式 patch）统一触发 `followScroll`：只要处于底部就持续跟随，手动拉回底部即恢复自动跟随。无 `ts` 的历史消息不显示时间。

**上下文压缩**：模型实际读到的上下文只来自 Agent 记忆 `thread:*`（checkpointer），显示层 `chat:*` 不参与 prompt——因此压缩只替换记忆、不动聊天记录。仓库 `compressThread(chatKey)`：把 wire 消息拼成对话稿（超长掐头留尾）→ 用 `pickAssistant()` 发一次独立摘要请求（不走 `agent.chat`，系统提示词 `COMPACTION_PROMPT` 要求保留需求/文件清单/决策/待办，≤800 字）→ 新记忆 = 摘要 user 消息 + assistant 确认 + `tailThread(thread, 2)` 最近两个完整回合原文 → 落盘，并在聊天流插入 `role: "compact"` 卡片（`count` 被压缩条数 + `summary` 可展开查看，模板复用 tool-row 折叠样式）。触发两路：① 手动——上下文胶囊明细面板里的「压缩上下文」按钮（`compressFromPanel` → `handleCompress` → `store.compress()`，`compacting` 状态防重入，对话过短/发送中弹 alert 说明）；② 自动——发送前（`send` 内，`ensureAgent` 之后）用 `contextInfo` 估算 `已用 + 本轮输入 ≈ chars/2 + 64`，达到窗口（`setContextWindow` 注入的菜单选定值，页面在 ready/切换时同步）即先压缩再对话，失败仅 console.warn 不阻塞。压缩只在两回合之间发生，chain 每回合收尾的 checkpointer.set 整体覆盖语义不受影响；水位显示要等下一回合的 `context_tokens` 回来才会下降。

**项目导航（标签制）**：每个项目一个网页标签，URL 以 `?p=<name>` 标识（草稿标签无 `p`）。顶栏品牌区——已进入项目时显示应用 Logo + 名称 + 渠道徽标 + 项目下拉按钮，右侧再并列小字号的当前会话标题 + 编辑按钮（`editSessionTitle` → senti-ui `prompt.js` 重命名，仓库 `renameSession` 同步 registry / 列表 / 顶栏）；草稿时显示「妙造 / 新应用 · 未创建」。项目名右侧下拉按钮（`st-icon-button` + `mdi:chevron-down`，草稿态同样显示）→ **左侧项目抽屉**（`.proj-drawer` + 遮罩，复用 `.panel-item` 列表项样式）：顶部「＋ 新建项目」按钮；项目清单每项含图标 / 名称 / 渠道徽标 / 目录名、「已打开」徽标（`openTabs`）与两步确认删除按钮。点击项：当前为空白草稿态（`currentAppName === ""`）且该项目**未在其他标签打开**时**在当前页内切换**——`openProjectTab` 直接调仓库 `selectApp(name)` 加载该项目并打开最近会话，收起抽屉（URL `p` 由 `syncUrlParam()` 自动补上）；目标项目已打开（`openTabs` 命中，「已打开」徽标同一数据源）则与已进入项目时一致聚焦那个标签，避免同一项目被两个标签同时接管。窗口名 `ai-builder-<name>` / `ai-builder-draft`；打开/聚焦统一走 `focusOrOpenTab(url, name)`——先 `window.open("", name)` 拿同名标签引用（已存在时**仅聚焦不导航**，避免 `window.open(url, name)` 对已存在标签执行同 URL 导航造成的整页刷新），拿到的是 `about:blank` 新空白标签时才补 `location.href = url`。（「＋ 新建项目」在草稿态同样只收起抽屉留在本页）。窗口名由 `syncTabName()` 跟随 `currentAppName` 实时同步（草稿 = `ai-builder-draft`，项目 = `ai-builder-<name>`，与 `syncUrlParam()` 同一处触发）——标签**原地切换**（草稿里生成落地 / 草稿里点项目）后必须改名，否则项目标签顶着 `draft` 旧名，再点「新建项目」会把该项目标签本身导航回草稿。「已打开」状态由跨标签感知维护：`BroadcastChannel("ai-builder-tabs")` 广播 `hello` / `alive` / `bye`（本标签 `announce(currentAppName)`，`beforeunload` 发 `bye`；打开抽屉时 `refreshAliveTabs()` 清空重探测）。URL `p` 参数由 `syncUrlParam()` 跟随 `currentAppName` 用 `history.replaceState` 同步（草稿落地为新应用后自动补 `p`，刷新不丢项目）。右侧 `.panel` 为「工具 / 技能」双 tab 的资源面板，`.panel-mask` 为 absolute 覆盖层。

**职责边界**：页面 `data` 是仓库状态的**视觉投影**——`ready()` 里 `store.subscribe()` 把 patch 事件键值直接赋给同名 data 字段，messages 事件细粒度应用到 `this.messages`（`applyMessageEvent`）；`proto` 方法是对仓库方法的薄代理（会话两步删除 `confirmingDelSession` + `removingSid` 折叠动画——删除按钮平时为圆形、确认时形变圆角方形，二次点击后 item 高度/透明度归零再真正删除；项目两步删除 `confirmingDelApp` 与 `panelOpen` / `panelTab` / `projDrawerOpen` / `openTabs` / `input` / `atBottom` 等纯 UI 状态留在页面）。业务变更一律调仓库方法，页面不直接改业务数据。
