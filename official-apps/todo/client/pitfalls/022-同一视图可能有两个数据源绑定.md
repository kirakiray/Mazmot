# 022 · 把过滤下沉到 getter 后，忘了同一个视图的 o-fill 还绑着未过滤的旧数组

**症状**：给「已归档 / 垃圾桶」两个视图加上「跟随左栏分组」的过滤后，运行场景用例失败：

```
「工作」下的垃圾桶不应出现其它分组的条目，实际 默认项
```

而**页面其它部分全都对**——底栏「垃圾桶 0 项」、空状态「「工作」的垃圾桶是空的 🗑」、
视图标签的徒标都已经是过滤后的数字。也就是说：**计数是过滤后的，列表却是全量的**，
两者同屏不一致。

**根因**：同一个视图的「数据」和「计数」走的是两条独立的取值路径。本次改动只把
getter 层（`trashTodos` → 新增 `scopedTrashTodos`）和底栏/徒标/空状态改成了过滤后的 getter，
但垃圾桶列表的 `<o-fill :value="trashTodos">` 里写的仍是**原始数组名**——它不带任何过滤，
于是列表照旧渲染全量条目。注意这个视图的计数与空状态都不是从 `visibleTodos` 来的
（模板里它们各自读 `scopedTrashTodos.length` / `isListEmpty`），所以只改 getter 不会报错、
也不会自动同步。

**正确姿势**：

1. 改「视图数据范围」时，**先搜模板里所有 `:value="…"` 的绑定**，逐个确认它引用的 getter
   是不是新的那个：本项目垃圾桶视图绑 `scopedTrashTodos`、归档视图绑 `archiveGroups`（内部已用
   `scopedArchivedTodos`）、列表视图绑 `visibleTodos`——三处都要过一遍，别只改 getter 定义。
2. 别信「响应式会自动同步」的直觉：`o-fill` 只认它自己 `:value` 里的表达式，页面里另有一份
   计数/文案被改成过滤后，只会让不一致更隐蔽（数字对了 → 误判整体已生效）。
3. 排查手法：同屏对照「底栏计数」与「列表条数」，两者口径不同即为本坑；再用
   `preview eval` 数 `shadowRoot.querySelectorAll('.item').length` 拿实证。
