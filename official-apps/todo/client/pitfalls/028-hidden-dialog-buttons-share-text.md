# 028 · 用例里按文案点按钮会点到「隐藏弹窗」里的同名按钮

## 症状

新增「移动分组」用例，验证「点浮层里的取消应关闭浮层」时挂掉：

```
✗ 移动分组  └ 失败步骤「eval await T.openMove('搬家'); …」
  Error: 点「取消」应关闭浮层
```

应用侧点「取消」明明是好的（手动实测过），但用例里点了没反应。

## 根因

用例里的通用助手 `T.btn(text)` 是「在**整个页面 shadowRoot** 里找第一个文本等于 `text` 的 `st-button`」：

```js
T.byText = (sel, t) => T.q(sel).find((e) => T.tx(e) === t) || null;
T.btn = (t) => T.click(T.byText('st-button', t));
```

而本项目有 4 个 `st-dialog`，**关闭状态只是面板不显示，light DOM 里的按钮一直都在**。模板顺序是「添加任务弹窗 → 分组弹窗 → 任务详情弹窗 → 移动浮层 → 颜色弹窗 → 二次确认弹窗」，于是 `T.btn('取消')` 命中的是**添加任务弹窗**里的「取消」（执行了 `closeAdd()`，无害），移动浮层当然还开着。

同类坑还有：`T.btn('添加')`、`T.btn('保存')`、`T.btn('关闭')`、`T.btn('确认')` —— 这些文案在多处弹窗里重复出现，按文案全局直找都可能命中错的按钮。

## 正确做法

**把选择器限定到唯一容器里**，不要用全页文案直找：

```js
T.click(T.byText('.move-actions st-button', '取消'));
```

或者按 `T.dlg()`（当前 `[open]` 的弹窗）内部再找（本项目 `T.dlgBtn(t)` 就是这么写的）。本项目的经验：

- 弹窗内的操作 → 走 `T.dlgBtn(文案)`（**先锁定打开的那个弹窗**）；
- 自建浮层（`.move-actions` 等）→ 走 `T.byText('.xxx st-button', 文案)`；
- 行内按钮 → 按 `title` / 语义类名挑（`.pin-btn` / `.move-btn`、`title` 含「删除」），不要用下标（踩坑 025）。

## 教训

「页面上只有这一个「取消」按钮」和「这个容器里只有一个按钮」是同一种脆弱假定。**文案类选择器一律带容器前缀**；写用例时先在页面里数一下同名文案的按钮有几个（`T.q('st-button').filter(...)`），再决定选择器。
